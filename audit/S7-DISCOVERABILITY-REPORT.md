## 2. T28 — robots.txt and sitemap.xml

Both are **generated at build time** by the `seo-files` plugin from
`VITE_SITE_ORIGIN` + `src/data/projects.js`, so their URLs cannot drift from the ones in
`index.html`. They are also served correctly by the dev server (middleware), not only in
`dist`.

`dist/robots.txt` (text/plain):
```
User-agent: *
Allow: /

Sitemap: <origin>/sitemap.xml
```

`dist/sitemap.xml` — **10 real URLs**, each with `<lastmod>`:

```
/  /about  /projects  /projects/coding-ninjas  /projects/bmw
/experience  /education  /certifications  /achievements  /contact
```

Ten rather than nine, because `/projects/:slug` is a route *pattern*, not a URL: it
expands into the two project pages that actually exist. Listing the pattern itself
(`<loc>…/projects/:slug</loc>`) would be an invalid URL that crawlers discard, so the two
real pages are listed and the projects index is kept — every URL in the file resolves.
Parsed with `xml.etree`: well-formed, root
`{http://www.sitemaps.org/schemas/sitemap/0.9}urlset`, 10 `loc` entries.

**The origin you must set** — `VITE_SITE_ORIGIN`, one value, in `.env` (copy
`.env.example`) or Vercel → Project → Settings → Environment Variables:
```
VITE_SITE_ORIGIN=https://your-domain.com     # no trailing slash
```
Until it is set, all four artefacts say `https://REPLACE-WITH-YOUR-DOMAIN` and the build
prints a warning naming this variable. Verified both ways:

| build | `index.html` | `robots.txt` | `sitemap.xml` | warning |
|---|---|---|---|---|
| placeholder (default) | 6 hits | 2 | 10 | printed |
| `VITE_SITE_ORIGIN=https://ashish-kumar.example.app` | 6 hits | 2 | 10 | correctly silent |

After setting it: redeploy, then confirm with
`grep -c REPLACE-WITH-YOUR-DOMAIN dist/index.html dist/robots.txt dist/sitemap.xml` → all `0`.

## 4. T20 — the contact address is out of the bundle

**Endpoint.** `src/sections/Contact.jsx` now posts to the FormSubmit **alias** you
supplied, with an environment override:
```js
const FORM_ALIAS = 'dbcb9c89ab8b18aaa83b8792882d8a96'
const FORM_ENDPOINT = import.meta.env.VITE_CONTACT_ENDPOINT || `https://formsubmit.co/ajax/${FORM_ALIAS}`
```
FormSubmit's own documentation confirms this is the supported way to keep an address out
of the page source: the aliased endpoint routes to the same inbox, and the address stays
unknown to bots and visitors.

**Proof (the acceptance grep):**
```
$ grep -r "ashish1492a@gmail" dist/
  ✓ nothing (no matches)
$ grep -ro "formsubmit.co/ajax/[a-z0-9]*" dist/assets/*.js
  formsubmit.co/ajax/dbcb9c89ab8b18aaa83b8792882d8a96      ← the alias is what ships
```

**Everything else that carried the address, and what it became**

|---|---|---|

| `index.html` (JSON-LD) | `"email": "mailto:…"` | removed; `url` + `image` added |
| `src/sections/Contact.jsx` | lime `mailto:` CTA showing the address; error copy naming it | CTA is "Or fill the form" (jumps to the form); error copy says "reach me on LinkedIn or GitHub below" |

On the rendered `/contact` page: **0 `mailto:` links**, the literal address does not
appear in the DOM, and the alias is not visible to visitors (it exists only in the JS).
Nothing new was added under the form — **C1 still holds**: no third-party disclosure line.

**If the alias is ever wrong or revoked**, messages silently stop arriving. To confirm
delivery yourself: open the deployed site, submit the form once with a real message and

own success message only reflects FormSubmit's HTTP response.

## 5. Honest limitations

1. **FormSubmit delivery is unverified.** This sandbox's network is allow-listed to GitHub
   only — `curl https://formsubmit.co` cannot connect — so I could not POST a test
   submission. The endpoint *construction* and the bundle grep are verified; actual
   delivery of a message through the alias is not. Test it from the deployed site (§4).
2. **Social-crawler rendering is unverified.** Whether WhatsApp/LinkedIn/X actually draw
   the preview requires a public URL; the tags and the 1200x630 PNG are verified locally.
   After deploying with the real origin, the usual check is the platform's own debugger
   (e.g. LinkedIn Post Inspector) or pasting the link into a chat.
3. **The address still exists in git history.** It is present in the repository's very
   first commit (`85f12aa Add files via upload`), which is public. Removing it from the
   current files (done) does not remove it from history — anyone running
   `git log -p` or GitHub's search over an old commit can still find it. Options, in
   increasing effort: leave it (the *site* no longer ships it, which is what scrapers
   read); make the repository private; or rewrite history
   (`git filter-repo --replace-text`) and force-push — destructive, changes every commit
   hash, and I will not do it without you explicitly asking.
4. **No Lighthouse run**: no browser is available here, so the manifest/icon checks are
   structural (parse, sizes, MIME types, HTTP 200) rather than a Lighthouse score.
